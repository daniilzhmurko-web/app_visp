# Учебный тренажёр ЦАФАП — многофайловый сайт

Сайт работает **без сервера**: достаточно открыть `index.html` двойным щелчком (протокол `file://`) или
положить папку на любой статический хостинг. Интернет не нужен — шрифты иконок и Chart.js лежат в `vendor/`.

> Все данные в базах **синтетические**: персоны, номера, VIN, документы и штрафы вымышлены.
> Снимки фиксации — **не фотографии**, а процедурно нарисованные сцены.

## Структура

```
index.html            ← тренажёр (вход → 6 этапов → отчёт)
photo-studio.html     ← студия: промпты для нейросети, нанесение вымышленного номера, ZIP с готовыми фото
manual.html           ← руководство пользователя (6 этапов, 72 шага, базы, фотоматериал, для преподавателя)
databases.html        ← просмотр баз данных (поиск, постраничный вывод, CSV, предпросмотр снимков)
css/main.css          ← стили
js/
  db/db.js            ← слой доступа к базам (CAFAP_DB): поиск по номеру/VIN/кузову/двигателю/ФИО, выборки для сценариев
  core/token.js       ← токен подлинности (ФИО из токена, печати в отчёте)
  core/snapshot.js    ← путь к снимку: SVG или JPG/PNG (приоритет растровой копии, откат по цепочке файлов)
  core/app.js         ← каркас: вход, навигация, панель заданий, отчёт
  core/maptiles.js    ← локальная подложка карты: тайлы из assets/map + онлайн-провайдеры
  stages/stage1..6.js ← этапы 1–6
data/                 ← БАЗЫ ДАННЫХ (генерируются, не править руками)
  fis_gibdd_m.js      ← ФИС ГИБДД-М: владельцы, водительские удостоверения, ТС, розыск, ограничения
  fixations.js        ← база фиксаций: параметры снимков, результат OCR
  gis_gmp.js          ← ГИС ГМП: начисления и платежи по штрафам
  fssp.js             ← ФССП: исполнительные производства
  ai_photos.js        ← фото, созданные ИИ (создаёт photo-studio.html)
  photos.js           ← пользовательские фото (по умолчанию пусто; создаёт tools/import-photos.js)
  fvf_complexes.js    ← реестр комплексов фото-видеофиксации (камер)
  nsi.js              ← НСИ: регионы, статьи КоАП, марки/модели, цвета, типы комплексов
assets/
  img/                ← логотип ЦАФАН, favicon
  snapshots/          ← 320 синтетических снимков фиксации (SVG), по одному на запись базы фиксаций;
                        ← рядом может лежать растровая копия .jpg/.png с тем же именем — она и показывается
  map/                ← реальная карта Москвы для этапа 5: 395 тайлов (9–13) + tiles.js — перечень тайлов
  photos/             ← реальные фото (появляется после tools/import-photos.js)
vendor/               ← Chart.js и Font Awesome (локально)
tools/                ← генератор баз и снимков (Node.js)
  build.js            ← сборка баз и снимков
  rasterize.js        ← SVG → JPG/PNG (растровые копии снимков)
  serve.js            ← локальный сервер тренажёра (http://localhost:8080)
  import-photos.js    ← импорт реальных фотографий
  fetch-map-tiles.py  ← загрузка/обновление архива тайлов карты (assets/map)
```

## Что откуда берётся

| Этап | Использует базы |
|---|---|
| 1 — Дашборд | **fvf_complexes** (камеры); **fis_gibdd_m** (очередь нарушений, окно «Запрос ФИС ГИБДД-М») |
| 2 — OCR | **fixations** (очередь, снимки, OCR-результат), **fvf_complexes** (метаданные комплекса), **fis_gibdd_m** (поиск владельца: розыск, ограничения, ОСАГО, ВУ) |
| 3 — Постановления | **fis_gibdd_m** (владельцы, ТС) |
| 4 — Почта/ФССП | **gis_gmp** (постановления, УИН, суммы, статусы оплаты — почтовая очередь, контроль оплат, ст. 20.25), **fssp** (исполнительные производства, статистика), **fis_gibdd_m** (адресаты), **nsi** (статьи) |
| 5 — Аналитика | **fis_gibdd_m** (реестр розыска), **fvf_complexes** (карта камер, реестр) |
| 6 — Администрирование | **nsi** (справочник статей КоАП) |

Не из баз (генерируются самим этапом): ленты событий и метрики этапа 5 (трафик, KPI операторов), пользователи
и роли этапа 6, часть статистики на дашборде этапа 1. Страница `databases.html` показывает ровно те таблицы, на которые опирается тренажёр.

Сценарные номера из заданий (`А177МС77`, `О917ММ177` и др.) всегда присутствуют в ФИС.
Номера можно вводить латиницей — они нормализуются в кириллицу (`A177MC77` → `А177МС77`).

## Карта камер (этап 5)

Карта построена на **Leaflet** (локально в `vendor/leaflet/`) с наложением: цветные точки — статус камеры,
полупрозрачные круги — «нарушений за сутки» (площадь пропорциональна значению). Легенда и переключатель слоёв — внутри карты,
клик по строке реестра подводит карту к камере.

**Подложка по умолчанию — реальная карта Москвы, вложенная в архив сайта** (`assets/map/`, 395 тайлов,
масштабы 9–13). Она читается с диска и работает **без интернета** — это сделано потому, что публичные
провайдеры тайлов (особенно `tile.openstreetmap.org`) блокируют массовые запросы и подставляют
картинку «Access blocked». Атрибуция OpenStreetMap выводится в углу карты.

Кнопка **«Карта (из архива)»** в шапке карты открывает меню подложек:
`Карта (из архива)` → `OpenStreetMap (онлайн)` → `Esri Street Map (онлайн)` → `Схема (без карты)`.
Если выбранного локального тайла нет (область за пределами архива), слой догружает онлайн-зеркало OSM;
если онлайн-провайдер заблокирован — автоматически включается условная схема (МКАД, ТТК, Садовое кольцо, Москва-река).

Обновить/дополнить архив тайлов: `python3 tools/fetch-map-tiles.py` (качает OSM-тайлы Москвы и пишет `assets/map/tiles.js`).

Из этапа 1 («Камеры ФВФ») клик по камере открывает эту же карту с выбранной камерой в центре.

## Печать постановлений и отчётов (PDF)

* **Этап 4 → «Очередь печати»**: кнопка печати у строки открывает настоящее печатное окно браузера
  с формой постановления (номер, нарушитель, адрес, статья, сумма, срок оплаты) и **блоком электронной
  подписи** должностного лица, вынесшего постановление: ФИО и должность, номер сертификата ЭП, срок
  действия, хэш подписи (SHA-256), росчерк подписи, код проверки и штамп «Подписано ЭП».
  В диалоге печати выберите «Сохранить как PDF» — получается готовый документ. Кнопка «Печатать все»
  печатает весь пакет постановлений одним заданием.
* **Этап 5 → «Отчёты»**: кнопка «глаз» открывает отчёт в модальном окне (сводка по базам ФИС/ГИБДД, ГИС ГМП,
  ФВФ и ФССП: KPI, топ нарушений по статьям, нагрузка на комплексы, взыскание, качество распознавания номеров).
  Кнопка «Скачать» сохраняет готовый самодостаточный HTML-файл, кнопка «Печать / PDF» — печатную форму.

Печать выполняется в скрытом `iframe`, поэтому страница тренажёра не перерисовывается и не мешает.

## Токен доступа

Как в SOPS-тренажёре: токен вида `base64(JSON).подпись` вставляется на экране входа или передаётся ссылкой
`index.html?token=…`. ФИО берётся из токена и блокируется; в отчёт попадают `token`, `renderSeq`,
`cadet.syncTag`, `uiInstance`. Без токена вход работает по ФИО и номеру взвода. Подпись страница не проверяет —
это делает проверяющий (`universal_checker`).

## Пересборка баз и снимков

```
node tools/build.js            # базы (data/*.js) + снимки (assets/snapshots/*.svg)
node tools/build.js --no-snap  # только базы
```

Снимок рисует **переднюю часть автомобиля** — так, как снимает камера ЦАФАП: капот, лобовое стекло,
фары, решётка радиатора, бампер с номерным знаком (раньше был вид сзади). Параметры сцены
(свет, погода, дорога, расстояние, состояние номера) заданы в записи фиксации, рисует их
`tools/lib/snapshot-renderer.js`; рамки детектора («фото нарушения», «выделенные номера») считаются
по той же геометрии и попадают ровно на фары и номер.

Сборка детерминирована: тот же seed — те же данные. Пересборка меняет только `geom` в
`data/fixations.js` (координаты рамок под новую геометрию) — все персоны, номера, VIN, начисления
и сами снимки по содержанию не меняются.

Генерация детерминирована (seed в `tools/lib/db-builder.js`). Объём и состав настраиваются там же:
число владельцев (`PERSONS`, `ORGS`), ТС (`TOTAL`), начислений, фиксаций (`TOTAL_FIX`).
Параметры сцены снимка (кузов, цвет, свет, погода, состояние номера) заданы в записи фиксации,
рисует их `tools/lib/snapshot-renderer.js`.

## Замена снимков SVG на JPG/PNG (растровые копии)

Снимок фиксации в базе (`data/fixations.js`) хранится путём к файлу. По умолчанию это векторная сцена
`assets/snapshots/FIX-XXXXX.svg`. **Рядом с ним может лежать растровая копия с тем же именем**
(`FIX-XXXXX.jpg` / `.jpeg` / `.png` / `.webp`) — и тренажёр покажет именно её. Связь с базой не меняется:
остаются те же номер, результат OCR, геометрия объектов, зелёные рамки детектора и кадрирование 4 кадров.

**Как заменить (два способа)**

1. **Просто положить файлы** — скопируйте `FIX-00001.jpg`, `FIX-00002.jpg` … в `assets/snapshots/`.
   Больше ничего делать не нужно: при открытии снимка тренажёр сам проверит jpg → jpeg → png → webp → svg
   и покажет первую существующую картинку. Работает и при открытии сайта через `file://`.
2. **Пересобрать базу** (рекомендуется) — `node tools/build.js`. Тогда в базе фиксаций путь сразу будет
   вести на растровую копию (`file` → `assets/snapshots/FIX-00001.jpg`, исходный путь сохраняется в `svgFile`),
   и лишних запросов к несуществующим файлам не будет.

**Как сделать сами JPG/PNG из SVG** — `tools/rasterize.js`:

```
node tools/rasterize.js                    # все снимки assets/snapshots → JPG (1280×720)
node tools/rasterize.js --format png       # …в PNG
node tools/rasterize.js --scale 2          # 2560×1440
node tools/rasterize.js --only-missing     # не перегенерировать готовые
node tools/rasterize.js --from ./my_svgs --out ./my_png   # произвольные SVG
```

Инструменту нужен headless Chromium: `npm i playwright && npx playwright install chromium`.
Без него используется `rsvg-convert` / `inkscape` / ImageMagick, если они установлены.
Рендер идёт через Chromium, поэтому сохраняются фильтры сцены (шум, размытие) и кириллица на номере.

**Важно:** кадрирование кадров и рамки детектора считаются в долях кадра, поэтому размер картинки
(1280×720, 1920×1080 и т. п.) значения не имеет — менять геометрию в базе не нужно.

**Выгрузка доказательств.** Кнопки «Скачать кадр PNG», «Скачать исходный файл», «Скачать все 4 кадра»
и «Печать» работают, когда сайт открыт через веб-сервер (в режиме `file://` браузер запрещает
переносить локальные картинки в PNG). Локальный сервер без зависимостей:

```
node tools/serve.js          # http://localhost:8080
node tools/serve.js 9000     # другой порт
```

## Реальные фотографии вместо синтетических

Тренажёр показывает «фотоматериал» в формате реальных комплексов: 4 кадра (обзорный, следующий через 0,6 с,
фото ТС, увеличенный номер) с зелёными рамками детектора и текстовым блоком (нарушение, комплекс, дата и время
с миллисекундами, адрес, направление, координаты). Синтетические снимки и реальные фото показываются одинаково.

**Порядок работы**

1. Подберите фотографии (источники — ниже) и положите в одну папку. Для каждого фото желательна разметка YOLO
   с тем же именем и расширением `.txt` (`класс xc yc w h` — рамка номера в долях кадра).
2. **Замените настоящие номера вымышленными** (рекомендуется всегда):
   `python tools/replate.py <папка_с_фото> <выходная_папка>` — рисует вымышленный номер по рамке
   и записывает `plates.csv`. Нужен Pillow (`pip install pillow`) и шрифт с кириллицей (`--font arialbd.ttf`).
3. Импортируйте: `node tools/import-photos.js <выходная_папка> --source "URL набора" --license "CC BY 4.0"`.
   Инструмент копирует фото в `assets/photos/`, создаёт вымышленных владельца и ТС в ФИС, запись в базе фиксаций,
   пишет `data/photos.js` и `assets/photos/ATTRIBUTION.txt` (источники и лицензии для соблюдения условий CC BY).
4. Доля реальных фото в очереди этапа 2 задаётся `CAFAP_REAL_SHARE` в начале `js/db/db.js` (по умолчанию 0,5).

Без файла разметки рамки в «фотоматериале» будут приблизительными (фото всё равно покажется).

**Где взять фото (проверяйте лицензию каждого набора перед использованием)**

| Набор | Что внутри | Лицензия по описанию |
|---|---|---|
| Hugging Face: `AY000554/Car_plate_detecting_dataset` | ~25 500 фото автомобилей с российскими номерами + разметка YOLO (рамка номера); основан на AUTO.RIA Numberplate Dataset (Nomeroff Net) | оригинальный набор — CC BY 4.0 |
| Roboflow Universe: `g15/car-license-plates-rus`, `neopoleones/car-license-plates-dataset` и др. | детекция российских номеров | CC BY 4.0 (на странице каждого набора) |
| Roboflow Universe: `license-plates-f8vsn` | подмножество Open Images | изображения CC BY 2.0, разметка CC BY 4.0 |

Это в основном объявления о продаже автомобилей и любительские снимки, а не кадры камер ЦАФАП. CC BY требует
указания авторства — `ATTRIBUTION.txt` заполняется автоматически, если указаны `--source` и `--license`.
Скачиваются эти наборы вручную (инструмент сам ничего не загружает из сети).

**Юридическая оговорка.** Фотографии с читаемыми настоящими номерами и вымышленными владельцами — это
недостоверные сведения о реальных автомобилях и их владельцах. Используйте `replate.py`, фото с согласия владельцев
или собственные снимки. Реальные материалы ГИБДД/ЦАФАП (постановления, фотоматериалы) с чужими данными в учебный
сайт загружать не следует. По вопросам персональных данных проконсультируйтесь с юристом.

## Фотореалистичные снимки, созданные нейросетью (photo-studio.html)

Чтобы вместо нарисованных SVG показывались «настоящие на вид» кадры (город, улица, разные машины), снимки генерируют в
ChatGPT или другом генераторе изображений, а студия (`photo-studio.html`, кнопка «Студия фото» на странице баз) привязывает
их к записям базы фиксаций. Всё работает в браузере, без Node и Python.

1. Откройте `photo-studio.html`, выберите запись слева (слева — марка, цвет, свет, погода, тип дороги).
2. Нажмите «Копировать» в блоке «Промпт» и вставьте в генератор. Выберите стиль: «камера над дорогой» (как у комплекса)
   или «снято сзади, как с соседнего автомобиля» (как фото-эталон). Кнопка «Промпты (CSV)» выгружает промпты для всех записей.
3. Сохраните картинку (png/jpg/webp) и перетащите в студию. Имя файла вида `FIX-00047.jpg` выбирает запись автоматически.
4. Отметьте номерной знак главной машины (прямоугольник или 4 угла). Студия закрывает его **точным вымышленным номером из базы**
   (состояние — грязный/снег/выцветший — берётся из записи). Это обязательно: нейросети искажают буквы на номерах, а симулятор сверяет номер с ФИС.
5. Если на картинке читаются номера других машин — режим «Закрыть чужие номера», обведите их (область пикселизируется).
6. «Принять в набор» → «Скачать ZIP». Распакуйте архив в корень сайта с заменой `data/ai_photos.js`
   (создаются `assets/photos_ai/FIX-xxxxx.jpg` и манифест с рамками номера и машины).
7. Обновите `index.html`: для этих записей вместо SVG показывается фото, «фотоматериал» (4 кадра, рамки) строится по нему.

Достаточно 20–60 кадров: каждая подменённая запись показывается не более двух раз, а фото попадают в верхнюю часть очереди этапа 2.
Незаменённые записи остаются синтетическими. Условия использования сгенерированных изображений проверьте в правилах вашего генератора;
номера-вымыслы теоретически могут совпасть с чьими-то настоящими — это обычное допущение для учебных материалов.

## Настройка скидки на штраф

В начале `js/core/app.js`: `const CAFAP_DISCOUNT = {pct:50, days:20};`.
Сейчас стоят значения исходного курса; ряд изданий указывает, что с 01.01.2025 для большинства
нарушений действует 25% при оплате в течение 30 суток (`{pct:25, days:30}`) — сверьте с действующей
редакцией КоАП. Подсказки, расчёты и вопрос теста подстраиваются автоматически.

| «Нет данных конкретного дела, поиск ничего не находит» (этап 1) | В окне поиска не было подсказки о формате, а шаг требовал найти конкретный г/н | `s1_openSearchModal()`/`s1_doSearch()`: в окне сразу перечислены 4 реальных дела очереди (номер, г/н, владелец, камера) — клик по ним подставляет значение и выполняет поиск; г/н подставляется автоматически; при отсутствии результатов показывается тот же список реальных дел. Номер дела ищется без учёта регистра и разделителей |
| «После „Подписать ЭЦП“ автоматически переносит с этапа 3 на этап 4» | В трёх местах был прямой `switchStage(4)` сразу после подписания | `s3_goToStage4()`: переход к этапу 4 — только по явной кнопке «Перейти к Этапу 4»; если в этапе 3 остались невыполненные шаги, показывается подтверждение с подсказкой «следующее действие». В модалке подписи основная кнопка — «Продолжить в Этапе 3» |
| «Кнопка „Отправить“ видна только при наведении» | В `css/main.css` была переменная `--post`, которая нигде не объявлена: `background:var(--post)` не срабатывал, текст оставался белым на белом фоне | В `:root` добавлено `--post:#C62828`; `.btn-post` и штамп письма получили запасной цвет |
| «Кнопка „Отправить партию“ отсутствует» | Та же причина: кнопка была в разметке, но оставалась белым по белому | Исправлено вместе с предыдущим пунктом (кнопка в карточке «Управление почтовой отправкой») |
| «Полное пояснение шага появляется только после нажатия на правильный блок» | Указатель текущего шага (`quest[n].step`) не двигался после выполнения шага — панель продолжала показывать уже сделанный шаг | `syncQuestPointer()` в `js/core/app.js`: текущим считается первый невыполненный шаг; вызывается из `s1…s6_markQuest()`. Кнопка «Далее» больше не перескакивает через шаги |
| «Нижние кнопки в блоке „Сертификация“ не видно полностью» | `.cert-container` с `overflow:hidden` сжимался во flex-колонке и обрезал нижние метки этапов | `.cert-container{flex:0 0 auto}`; `--inst` увеличен до 248 px, чтобы пояснение шага не обрезалось; отступ под панелью заданий пересчитывается после каждой перерисовки (`syncInstSpace()`) |
| «Не нажимается на уведомление» / «нет кнопки „Синхр. с ФБД МВД“» / «задание не отмечается выполненным» | Уведомления правой панели были обычными `div` без обработчика; в разделе НСИ этапа 6 не было кнопки «Синхр. с ФБД МВД» | Уведомления открывают карточку в новой модалке `#notifModal` и закрывают шаг «Изучение системных уведомлений»; в НСИ добавлена кнопка «Синхр. с ФБД МВД» (`s6_syncFBD()`) |

Дополнительно: описания шагов теперь берутся из одного источника (`s{n}_questSteps` каждого этапа),
поэтому после переключения между этапами панель заданий не показывает общие сокращённые подсказки,
а подробное пояснение текущего шага.

## Просмотр дела в очереди нарушений (этап 2)

Кнопка **👁** в столбце «Действия» полной очереди (этап 2 → «Очередь») открывает полноценную
карточку дела `#caseViewModal` (`s2_openCaseView(id)`):

* снимок с камеры ФВФ с рамками детектора и кнопкой «Фотоматериал (4 кадра)» — материал открывается
  именно по выбранному делу (`s2_openPhotoMaterial(id)`);
* «OCR-результат и сверка с ФИС ГИБДД-М»: номер, распознанный системой, и номер из базы ФИС —
  расхождение подсвечивается, показывается уверенность OCR и измеренная скорость;
* «Данные нарушения»: дата/время, адрес, полоса, статья КоАП, штраф, срок оплаты;
* «Метаданные комплекса»: ID, модель, поверка, СТС, погрешность, координаты;
* доказательная база;
* действия: «Открыть в OCR-верификации» и «Исправить госномер вручную» (для дел с ошибкой OCR).

Дополнительно закрыты два незасчитываемых шага этапа 2: «Просмотр очереди нарушений»
(отмечается при открытии раздела) и «Обработка дела с ошибкой OCR» (отмечается, когда дело
с ошибкой открыто в OCR-верификации).
