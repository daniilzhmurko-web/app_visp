# ФИС ГИБДД-М — симулятор с подключаемыми базами

**Подробное руководство пользователя — файл `manual.html` (открывается двойным кликом).**

## Запуск на своём компьютере (Windows / macOS / Linux)
Python и интернет для работы НЕ нужны. Нужен только браузер (Chrome, Edge, Firefox).
1. Скачайте архив fis-gibdd.zip и **распакуйте его целиком** (правый клик -> «Извлечь всё»).
   Не открывайте index.html прямо из архива: рядом должны лежать папки app, data, docs.
2. Откройте папку fis-gibdd и дважды щёлкните **index.html**.
3. На экране входа дождитесь надписи «Базы подключены» (около 4 секунд) и нажмите «Войти в систему».
Если вместо этого написано «Автономный режим» — рядом с index.html нет папки data (проверьте распаковку).

## Обновление баз (по желанию, нужен Python 3.8+)
Windows: дважды щёлкните **update_data.bat**. macOS/Linux: запустите **update_data.sh**.
Скрипт заново создаёт базы, проверяет их целостность и пересобирает справочник.
Если Python не установлен: https://www.python.org/downloads/ (при установке отметьте «Add python.exe to PATH»).
Вручную (в командной строке, из папки fis-gibdd):
    python tools\generate_data.py            (на macOS/Linux — python3 tools/generate_data.py)

## Структура
    index.html              интерфейс и движок симулятора
    manual.html             руководство пользователя (17 разделов со скриншотами)
    app/
      datastore.js          загрузчик баз (FISDATA): подключает пакеты тегами <script>, работает по file://
      data-integration.js   связывает базы с симулятором: поиск, проверка паспорта (ГУВМ),
                            межведомственные запросы, справочник, подсказки инструктора
    data/
      manifest.js           список наборов, число записей, типы полей, дата формирования
      js/*.js               пакеты данных (шарды по ~4000 строк), ТОЛЬКО ДЛЯ ЧТЕНИЯ
    docs/
      kb/*.md               инструкции (правятся в любом редакторе)
      regulations/*.md      нормативные выдержки
      kb.js                 собранный справочник (результат tools/build_docs.py)
    assets/
      logo.png, favicon.png   логотип и герб (уже встроены в index.html, здесь — для справки)
    update_data.bat / .sh   одним щелчком обновить базы (Python)
    tools/
      generate_data.py      генератор синтетических баз (фиксированный seed)
      validate.py           проверка целостности: уникальность, ссылки между базами, форматы
      build_docs.py         сборка docs/*.md -> docs/kb.js
      set_logo.py           замена логотипа в index.html на ваш PNG (прозрачный фон, светлый логотип)

## Наборы данных (по умолчанию 109 718 записей)
Основные (загружаются при открытии страницы): граждане/ГУВМ 10 000 · ТС 10 000 · ВУ 8 000 · штрафы 20 000 ·
экзамены 1 243 · розыск 250 · движение спецпродукции 220.
Базы ведомств, **по 10 000 записей каждая** (подгружаются в фоне после входа): ФССП (исполнительные производства
и запреты на регистрационные действия) · ФНС · ФТС (таможенные декларации) · НЦБ Интерпол ·
ЕАИС ТО (диагностические карты) · Росавтодор (акты весогабаритного контроля). Справочник: 29 статей.

## Межведомственные запросы и задания
* В разделе «Сервисы ГИБДД» запрос уходит в выбранное ведомство, ответ приходит документом (номер, дата, поля, заключение)
  и сохраняется в «Журнале запросов». Журнал и решения попадают в JSON-отчёт курсанта.
* Передача штрафа в ФССП добавляет производство в базу ФССП — следующий запрос его уже покажет.
* 15 сценарных заданий (по 2–3 варианта на ГУВМ, ФССП, Интерпол+ФТС, ЕАИС ТО, Росавтодор, комплексную проверку):
  запросить сведения -> прочитать ответ -> выбрать решение. Правильное решение определяется ответами ведомств;
  запрос с чужим предметом не засчитывается, неверное решение — ошибка. В режиме «Экзамен» подсказок и пояснений нет.

## Как это работает
* Данные синтетические и связаны ключами (паспорт, ГРЗ, VIN): у каждого ТС есть владелец в persons,
  у каждого штрафа есть ТС, у каждого ВУ — гражданин.
* Каждая сессия получает свежие копии строк; изменения (регистрации, платежи, розыск) живут в памяти
  сессии и попадают в отчёт курсанта. Сами файлы не меняются.
* Даты в пакетах автоматически сдвигаются под сегодняшний день: просрочки, сроки ВУ и платежей
  остаются актуальными, сколько бы времени ни прошло после генерации.
* Учебные сценарии опираются на фиксированные записи: ТС в розыске К777АВ77, Х001РО77, М555НА50, Е777КМ78,
  снятый розыск А123ВЕ66; 14 пар дублей VIN; кандидаты на выдачу ВУ (Смирнов А.И., Белова Д.О., Громов Л.П.).
* Если папки data/ или docs/ нет, симулятор работает на встроенных учебных данных и сообщает об этом.
  Папка app/ обязательна.

## Обновить или расширить данные
    python tools/generate_data.py                # заново, тот же seed
    python tools/generate_data.py --seed 7       # другой набор
    python tools/generate_data.py --scale 3      # втрое больше (≈170 тыс. записей, загрузка дольше)
    python tools/validate.py                     # проверить целостность
    python tools/build_docs.py                   # пересобрать справочник после правки docs/*.md
Для новых наборов добавьте вызов write_set(...) в generate_data.py и использование в app/data-integration.js.

## Ограничения
* Только синтетика: реальные персональные данные в тренажёр загружать нельзя (ФЗ-152).
* Токен и контрольная сумма отчёта проверяются в браузере; серверной проверки нет.
* Нормативные выдержки учебные — сверяйте с действующей редакцией.
