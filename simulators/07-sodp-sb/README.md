# СОДП СБ — учебный тренажёр

**Сервис обеспечения деятельности подразделений собственной безопасности (СОДП СБ)** — интерактивный симулятор делопроизводства.
Все данные и документы **синтетические** (вымышленные ФИО, номера, события).

## Запуск
Откройте `index.html` двойным щелчком — сервер не нужен. Данные из `db/` и документы из `docs/` подключаются
обычными `<script src>` и относительными ссылками, поэтому работают и с диска, и с внутреннего сервера / статического хостинга.

Если открыть **только** `index.html` без папок (например, в окне предпросмотра) — симулятор работает на встроенном
генераторе с теми же данными; документы в этом случае показываются из генератора, а не из файлов.

## Структура
```
sodp_sb/
├─ index.html                 приложение (весь код в одном файле)
├─ db/                        «база данных» — JS-файлы с массивами записей
│  ├─ cases.js                531 дело (реестр дел)
│  ├─ candidates.js           301 проверка кандидатов
│  ├─ complaints.js           1008 обращений граждан
│  ├─ tasks.js                185 заданий
│  ├─ security_events.js      300 событий информационной безопасности
│  ├─ documents.js            6544 записи индекса документов (путь, тип, автор, дата)
│  └─ reg_ic / reg_fns / reg_egrn / reg_zags / reg_fssp .js
│                             синтетические «учёты» для раздела «Запросы в учёты»
│                             (ИЦ/ИБД-Ф, ФНС, Росреестр, ЕГР ЗАГС, ФССП): ~2000 записей
├─ docs/                      документы (HTML-файлы, по одному на запись индекса)
│  ├─ _assets/doc.css         оформление документов
│  ├─ _assets/available.js    флаг «папка docs доступна»
│  ├─ cases/<номер>/NN-тип.html
│  ├─ complaints/<номер>/NN-тип.html
│  └─ candidates/<номер>/NN-тип.html
├─ photos/                    301 фото кандидатов (kan-2024-0095.jpg …); по умолчанию — силуэты-заглушки
├─ missions/missions.js       миссии 7–27 (описания; можно править без изменения index.html)
├─ manual/sodp_sb_manual.html руководство пользователя
└─ build/                     исходники и сборка (необязательно)
   ├─ src/index.src.html, datagen.js, missions.src.js
   └─ make.js                 npm i jsdom && node make.js — пересобрать index.html, db/, docs/
```
Номера в путях латинизированы (`ГУСБ-2024-0298` → `gusb-2024-0298`), чтобы пути были безопасны для любых систем.

## Как подключить свои данные
1. Замените содержимое `db/*.js` своими (синтетическими!) записями в том же формате — одна запись на строку.
2. Для документов добавьте записи в `db/documents.js` и положите файлы по указанному в `path` пути (`.html`, `.pdf` — любой тип,
   который открывается в `<iframe>`).
3. Если в `db/` отсутствует хотя бы один из шести файлов, симулятор использует встроенный генератор.

## Запросы в учёты
Раздел «Запросы в учёты» и кнопки «Запросить в учёте» в карточке кандидата работают на **синтетических** моделях внешних баз
(`db/reg_*.js`, записи привязаны к номерам кандидатов `cand`). Реальные системы МВД и межведомственные сервисы не подключаются.
Запрос допустим только со служебным основанием; все запросы пишутся в журнал аудита и в итоговый отчёт (`registryQueries`).

## Фото кандидатов
Карточка кандидата и журнал проверок показывают `photos/<номер>.jpg`. Если файла нет — выводится силуэт.
Заглушки пересоздаёт `build/make_placeholders.py`; свои фото раскладывает `build/assign_photos.py` (см. `photos/README.txt`).

## Подписи в документах
Документы содержат учебную УКЭП («ДОКУМЕНТ ПОДПИСАН ЭЛЕКТРОННОЙ ПОДПИСЬЮ», герб, сертификат, владелец, срок действия); на рапортах, обращениях,
запросах и анкетах есть резолюция начальника отдела. Подписи детерминированы: у документа всегда один и тот же сертификат.

## Миссии
27 миссий в 7 направлениях (кадры, обращения, расследования, контроль, ИБ, аналитика, комплексные). Миссии 1–6 реализованы в коде,
7–27 описаны декларативно в `missions/missions.js`: шаги, проверяющие условия, «ловушки» со штрафом, вопросы с проверкой ответа.
Цели подбираются из базы индивидуально для каждого курсанта (по ФИО), поэтому у соседей разные варианты.
Формат миссии и список событий — в шапке файла `missions.src.js`.

## Режимы и вход
Вход: учебный пароль `Training2024`; поддерживаются токен-ключ преподавателя (поле на экране входа или `?token=`) и режим «Экзамен».
Свидетельство выдаётся после прохождения всех миссий.
